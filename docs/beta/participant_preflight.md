# Closed Beta participant preflight

This checklist is operational guidance, not legal advice. Have the participant agreement, NDA, and data-processing terms reviewed for the applicable jurisdictions before collecting real data.

## Before access

- [ ] Participant role and use case meet the Beta scope.
- [ ] Participant confirms authority to provide each SKU and source document.
- [ ] Product category is not excluded or high risk.
- [ ] Model provider, relay, data region, retention, and training policy have been disclosed.
- [ ] Approved agreement and any required NDA/DPA are recorded outside the public repository.
- [ ] Stable authenticated user ID is allowlisted to one participant project.
- [ ] Project expiry date and weekly interview schedule are set.
- [ ] Support, security, withdrawal, and deletion contacts are provided.

## Technical rehearsal

- [ ] Attempted cross-project read/write/export/delete returns unauthorized.
- [ ] Invalid type, oversize file, formula, macro, external link, archive bomb, and malformed row fixtures are rejected.
- [ ] Upload preview does not become generation input before human confirmation.
- [ ] Project clear deletes file bytes and structured facts.
- [ ] Logs contain identifiers and outcomes only, never product or output bodies.
- [ ] Model cost ceiling and emergency off switch are active.

## Before the first real task

- [ ] Participant downloads a blank import template.
- [ ] Every fact includes a source and evidence level.
- [ ] Missing, conflicting, and low-evidence fields are reviewed.
- [ ] Baseline timer starts before manual work.
- [ ] Two independent language reviewers are assigned without sharing scores.

## Exit

- [ ] Access revoked.
- [ ] Project deletion requested or retention choice recorded.
- [ ] Deletion result recorded without content.
- [ ] Final interview completed or declined.
- [ ] Any public-use permission is separate, explicit, and item-specific.
