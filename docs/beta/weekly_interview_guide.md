# Weekly Closed Beta interview guide

Duration: 30 minutes. Do not record product copy or confidential source material in public project files.

## Questions

1. What real task did you try this week, and did you finish it?
2. At which step did you first feel the workflow saved effort or reduced risk?
3. Which warning or block was useful? Which felt incorrect?
4. Did any imported fact, model output, translation, or rule make you distrust the result?
5. What did you still have to do outside LocalizeFlow?
6. Was the final file usable after review? How many substantive changes remained?
7. Would you use this again next week for the same category? Why or why not?
8. What single improvement would most change your answer?

## Categorization

Tag each blocker as `product`, `data`, `rule`, `model`, `usability`, or `none`. Record the evidence reference (task/run/issue ID), not the content body. Separate a product capability gap from a data-quality problem and a model failure.

## Weekly synthesis

- Completion and abandonment counts.
- Time to first generation and total task time.
- Fact, packaging, rule, language, and model failure counts.
- False-positive and false-negative gate reports.
- Continue / unsure / stop intent.
- Top three requested changes with participant counts.
- Decisions, owner, target week, and closed-loop status.
