# 从评论证据到双语商品内容

这是一条可离线检查的项目串联案例，不调用付费模型，也不自动模拟人工批准。

## 业务任务

为虚拟精华 `MV-SERUM-001` 制作美国英语与墨西哥西班牙语 Listing：利用消费者对舒适肤感的关注选择表达角度，同时拒绝没有商品事实支持的功效。

1. **评论 → 洞察。** [CrossBorder Voice](https://github.com/zugzwang-zg/crossborder-voice-agent) 提供评论分析和证据回查流程。LocalizeFlow 已保存的开发样本交接记录位于 `data/insights/consumer_insights.json`，不是从公开看板的 10 条样本重新计算的结论。
2. **洞察 → 商品事实。** `IN-US-001` 为舒适肤感方向，引用 `en_0530771`、`en_0603388`、`en_0095696`；相关商品证据包括 `MV-SERUM-001-F022` 和 `MV-SERUM-001-F024`。这些评论来自历史开发样本，完整原始记录不在公开仓库中，不能承诺读者能通过公开看板打开全部引用。
3. **拒绝无证据方向。** `IN-US-002` 的不黏腻/快速吸收方向为 `blocked`，关联的 C 级假设 `MV-SERUM-001-F038` 不能支持产品宣称。
4. **生成双语候选。** 使用冻结模板产生 US/MX Listing；英语洞察只是选题线索，不能据此推断墨西哥市场偏好，西语输出仍需本地评审。
5. **复检与反例。** 对候选运行质量检查；追加 `FDA-approved. Contains retinol.` 的版本必须阻断。
6. **人工终审。** 在网页编辑并确认后下载 JSON。修改文案或切换内容类型会撤销批准。脚本输出仅展示待复核候选，不伪造人工终审。

运行 `python scripts/run_evidence_case.py` 可在终端查看洞察、事实、双语候选和阻断结果。浏览器回归测试另验证批准、编辑失效、导出和评论抽屉流程。

当前联动是显式交接和演示，不是两个已部署服务之间的实时 API 集成。下一阶段再为经过授权的真实样本实现带数据版本、来源 ID 和用途限制的交接协议。
